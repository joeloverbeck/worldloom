# world-mcp

MCP retrieval server exposing the world index (`tools/world-index/`) as a structured API. Skills consume `mcp__worldloom__*` tools instead of reading raw markdown.

**Historical prior art**: `archive/specs/SPEC-02-retrieval-mcp-server.md`
**Phase**: 2 (read side plus SPEC-03 patch-engine delegation)
**Status**: Stdio MCP entrypoint registers 25 tools in `src/server.ts`; `validate_patch_plan` delegates to `@worldloom/validators`, also checks patch-engine ID allocation races, and returns an explicit validation status; `submit_patch_plan` delegates to `@worldloom/patch-engine`; `describe_capabilities` exposes server-start build metadata plus the deployed tool/enum contract for schema-currency checks; `get_record_schema` exposes world-canon, hybrid, and schema-backed story-bundle JSON schemas plus validator-sourced conditional block requirements; `describe_envelope_schema` exposes the patch-plan envelope and per-op payload schema contract for envelope assembly.

Explicit-world index-backed calls auto-recover and retry when `openIndexDb()` detects an index lifecycle error: `index_version_mismatch` runs `world-index build` in-process, and `stale_index` runs `world-index sync` in-process. Recovered responses include `freshness_audit.pre_call_index_version_was_old: true` and/or `freshness_audit.pre_call_index_was_stale: true`; persistent failures still return the original error code with recovery details. Patch-plan submit-time `index_stale` remains a separate fail-closed engine result.

## Tools

- `mcp__worldloom__search_nodes(query, filters, exhaustive?)` — searches FTS5 lexical node content. Default mode preserves capped, ranked retrieval. Use `exhaustive: true` for Rule 6 presence/absence scans across prose bodies; exhaustive mode returns every match sorted by `node_id` and adds `match_locations: ('body' | 'heading_path' | 'summary')[]` per row. `filters.story_slug` scopes search to indexed records for one story bundle; when omitted, default search remains world-canon / hybrid scope and does not surface story-bundle rows.
- `mcp__worldloom__get_node(node_id)`
- `mcp__worldloom__get_record(record_id, world_slug?, story_slug?, section_path?)` — retrieves one structured record. Atomic records return parsed YAML; hybrid records (`CHAR`, world-level `DA`, `PA`, `NCP`, `NCB`) return parsed frontmatter plus body sections. Story-local `DA` records and other story-bundle records (`PG`, `SE`, `BEL`, `SF`, `OBL`, `CNSQ`, `THR`, `SREL`, `STINT`, `STENT`, `STSTAT`, `STCHAR`, `STLOC`, `STOBJ`, `CLK`, `STSEC`, `STQ`, `STPLAN`, `STEMO`, `BR`, `CHC`, `SLT`, `SLB`, `SAU`, `SP`, `RSP`) require `story_slug` because their authored ids are unique only within `(world_slug, story_slug)`. `ARC_TRACE` is not a valid record class. Optional `section_path` narrows parsed atomic/story records by dotted path; for hybrid records it accepts `frontmatter`, `body`, `frontmatter.<key>`, and `body.<section>`. If an unprojected hybrid response would exceed the effective inline ceiling, the tool persists the full JSON response under the tool-results directory (`WORLDLOOM_MCP_TOOL_RESULTS_DIR` override, default `/tmp/worldloom-mcp-tool-results/`) and returns a bounded `delivery_status: "oversize_with_projection_suggestions"` response with `persisted_output_path` plus `suggested_section_paths` for immediate structured retry; `suggested_section_paths_omitted_count` appears only when the inline hint list is shortened to stay under the cap.
- `mcp__worldloom__get_records(record_ids, world_slug?, story_slug?)` — retrieves multiple structured records in one ordered response. `story_slug` scopes bundle-scoped story ids. Inline responses carry `delivery_status: "inline"` and each entry is `{ record_id, found: true, record, content_hash, file_path }` where `record` is the same successful response shape as `get_record`, or `{ record_id, found: false, error }` for a missing/invalid id. If the full ordered response would exceed the effective inline ceiling, the tool persists the inline-shaped JSON under the tool-results directory and returns `delivery_status: "persisted_with_summary"`, `persisted_output_path`, and `summary` metadata with slice hints such as `records[0].record.record`. Use when a packet, claim map, audit window, or dossier trace already produced a known id set and whole-class `list_records` would be too broad.
- `mcp__worldloom__get_records_field(record_ids, field_path, world_slug?, story_slug?)` — retrieves one field from multiple parsed atomic or story-bundle records in one ordered response. Each entry is `{ record_id, found: true, field_value, content_hash, file_path }` or `{ record_id, found: false, error }` for a missing/invalid id or missing field. `field_path` is the same `(string | number)[]` contract as `get_record_field`. Use for known-id batches where only one small field is needed across many records, such as `get_records_field(["CF-1", "CF-2"], ["distribution", "who_can_do_it"], "world")`.
- `mcp__worldloom__get_story_state_provenance(record_id, world_slug?, story_slug)` — retrieves story-event provenance for one story-bundle record from indexed `state_delta_create`, `state_delta_supersede`, and `creation_evidence` edges. Returns `{ record_id, record_class, creating_se_id, modifying_se_ids, evidence_records }`; `creating_se_id` is `null` when no authoring SE edge exists, and the arrays are empty when no modifying/evidence edges exist. Use this instead of scanning `stories/<story>/_source/events/SE-*.yaml` when a skill needs the SEs that authored or superseded a source record.
- `mcp__worldloom__verify_pg_state_hash(world_slug, story_slug, page_id)` — recomputes a committed PG record's `state_hash` for prose-attach Phase 2 without modifying `plan.plan_hash` first. Returns `{ recorded_state_hash, computed_state_hash, state_hash_match, recorded_plan_hash, computed_plan_hash, plan_hash_match }` plus provenance fields. `state_hash_match` is verdict-driving PG tamper evidence; `plan_hash_match` is the SPEC-72 advisory comparison against `pages-prose-plans/<page_id>.md`. If the prose plan file is absent, `computed_plan_hash` and `plan_hash_match` are `null` rather than a hard error.
- `mcp__worldloom__get_persisted_packet_slice(persisted_path, slice_path)` — retrieves a structured slice from package-persisted JSON emitted by `get_context_packet`, `get_records`, or `describe_envelope_schema` when they return `delivery_status: "persisted_with_summary"`. `slice_path` is a dot path such as `governing_world_context.nodes`, supports array indexes such as `records[0].record.record`, and supports id selection such as `local_authority.nodes[id=entity:donostia]`.
- `mcp__worldloom__list_records(world_slug, record_type, story_slug?, fields?, include_full_body?, filters?)` — returns indexed records for one supported atomic, hybrid, or story-bundle record type. Hybrid `record_type` values include `character_record`, `diegetic_artifact_record`, `adjudication_record`, `character_proposal_card`, and `character_proposal_batch`. Story-bundle `record_type` values require `story_slug` and include `story_entity_record`, `story_status_record`, `story_plan_record`, `story_emotion_record`, `belief_record`, `story_fact_record`, `story_event_record`, `obligation_record`, `consequence_record`, `thread_record`, `relationship_record_story`, `intention_record`, `story_location_record`, `story_object_record`, `pressure_clock_record`, `story_secret_record`, `story_question_record`, `branch_record`, `page_record`, `choice_record`, `storylet_record`, `story_diegetic_artifact_record`, `audit_record_story`, `promotion_record`, `storylet_batch_manifest`, and `remediation_storylet_proposal_card`. `section_record` enumerates atomic SEC-*-NNN YAML records only; WORLD_KERNEL.md narrative H2 spans are indexed as narrative sections for search/context and are retrieved directly by `get_record(record_id="<world>:WORLD_KERNEL.md:<H2 text>:0")` when needed. `filters` narrows rows before projection/full-body wrapping using parsed body field paths; values are scalars for exact match or arrays for any-of membership. Dotted paths address nested fields, for example `filters: { shape: ["routine_disruption", "reflection_dilemma"], content_intensity: ["mature", "tame"], "visibility.scope": "global_author_pool" }`. For array-valued record fields such as `domains_touched` or `visibility.allowed_branch_ids`, a scalar or array filter matches when any record value is present in the filter set. Atomic and story-bundle default/projection modes validate `fields` against top-level parsed-record keys from the filtered response rows; `record_id` is always included in projected records. Hybrid default/projection mode returns compact metadata (`record_id`, `record_kind`, `title`, `content_hash`, `file_path`) for the hybrid record types; `fields` is validated against those response-shape top-level keys. Unknown `fields` entries return `invalid_input` with `details.unknown_projection_keys` and sorted `details.accepted_projection_keys` instead of being silently dropped. Empty atomic/story-bundle result sets return `accepted_projection_keys: []` plus a `details.note` because accepted keys cannot be derived from matched rows. Hybrid filters can address frontmatter fields directly or through `frontmatter.<key>`. Set `include_full_body: true` for full-body mode, which ignores `fields` and returns `{ record_id, content_hash, file_path, body }` per record; atomic and story-bundle `body` values are parsed YAML except markdown-backed story surfaces such as `SLB` / `RSP`, and hybrid `body` is `{ record_kind, frontmatter, body_sections }`. Use full-body mode for deliberate bulk sweeps such as EPE Phase 6 invariant / Mystery Reserve firewall checks, continuity-audit cross-checks, and structured registry enumeration; use `filters` first for large storylet pools or other predictable hard-filter loads before falling back to persisted-output recovery.
- `mcp__worldloom__select_storylet_candidates(world_slug, story_slug, parent_page_id, turn_driver, intent_signature?, max_candidates?, include_rejection_summary?)` — returns a symbolic-prefilter shortlist (at most `max_candidates`, default 24) of storylet candidates for a story-bundle turn-cycle or commitment-block-authoring pipeline, plus a `filter_trace` recording per-stage counts. It never returns full SLT bodies; consumers fetch full bodies via `get_records(record_ids=requires_full_body_ids, story_slug=...)`. The pre-filter operates over indexed SLT projection columns and storylet edge projections; full predicate evaluation with alias substitution and Observer Firewall enforcement remains in the consumer-side turn-cycle evaluator running on the shortlist.
- `mcp__worldloom__get_record_field(record_id, field_path, world_slug?, story_slug?)` — returns a single field from a parsed atomic or story-bundle record without loading the full body. `field_path` is `(string | number)[]`: numeric segments index arrays, string segments address object keys. Examples: `get_record_field("SEC-ELF-1", ["touched_by_cf"])` for a CF list, or `get_record_field("CF-42", ["extensions", 0, "body"])` for one extension body.
- `mcp__worldloom__get_record_schema(node_type)` — returns the JSON Schema for a record class plus `node_type`, `source_path`, `referenced_schemas` keyed by `$id` URL, `required_fields`, and `conditional_blocks` for validator rules that are not expressible in the schema itself. Supported `node_type` values: `canon_fact_record`, `change_log_entry`, `invariant`, `mystery_reserve_entry`, `open_question_entry`, `named_entity`, `section`, `character_record`, `character_proposal_card`, `character_proposal_batch`, `diegetic_artifact_record`, `adjudication_record`, `extension_entry`, `story_entity_record`, `story_status_record`, `story_plan_record`, `story_emotion_record`, `story_fact_record`, `story_event_record`, `obligation_record`, `consequence_record`, `thread_record`, `relationship_record_story`, `intention_record`, `story_location_record`, `story_object_record`, `pressure_clock_record`, `story_secret_record`, `story_question_record`, `branch_record`, `page_record`, `choice_record`, `storylet_record`, `belief_record`, and `story_diegetic_artifact_record`. For `canon_fact_record`, `conditional_blocks` reports the `epistemic_profile` and `exception_governance` type taxonomies enforced by `record_schema_compliance`. Story-bundle record types without JSON-Schema files (`audit_record_story`, `promotion_record`, `storylet_batch_manifest`, `remediation_storylet_proposal_card`) are not exposed by this schema-discovery tool.
- `mcp__worldloom__get_neighbors(node_id, story_slug?, edge_types, depth)` — story-bundle authored ids require `story_slug`.
- `mcp__worldloom__get_context_packet(task_type, seed_nodes, token_budget, delivery_mode?, story_slug?, parent_page_id?)` — assembles the ranked retrieval packet. `story_bootstrap`, `story_character_profile`, `story_turn_cycle`, `commitment_block_authoring`, `branching_story_health_audit`, and `story_fact_promotion_to_canon` require `story_slug`. For `story_bootstrap`, the slug is the target bundle slug and `story_bundle_context` is `null` because the bundle does not yet exist; for the other story-pipeline task types, `story_bundle_context` is populated from indexed story-bundle records plus `STORY_KERNEL.md` frontmatter. When `parent_page_id` is supplied, or a `PG-*` id appears in `seed_nodes`, `story_bundle_context.selection_shortlist` embeds the projection-only `select_storylet_candidates` shortlist with `max_candidates: 24` and the default `player_action` turn driver; it preserves the capped visible storylet summary and never embeds full SLT bodies. World-canon task types return `story_bundle_context: null`. Story-pipeline `seed_nodes` should be realized `CHAR` ids and world anchors; story-local ids are warned-and-dropped with `story_local_seed_nodes_ignored`, and `NCP` / `NCB` authoring-proposal ids are warned-and-dropped with `authoring_proposal_seed_nodes_ignored`. Unresolvable `seed_nodes` are skipped, named in `task_header.warnings` as `seed_node '<id>' not found in world '<slug>'; skipped`, and do not prevent resolvable seeds or seed-independent governing context from being returned; when every seed is unresolved, the packet adds an aggregate seed-independent-context warning. When `token_budget` is omitted, `DEFAULT_TOKEN_BUDGET_BY_TASK_TYPE` uses `story_bootstrap: 18000`, `story_turn_cycle: 18000`, `commitment_block_authoring: 18000`, `canon_addition: 16000`, `propose_new_canon_facts: 15000`, `propose_new_characters: 15000`, `emergent_pressure_events: 15000`, `propose_new_worlds_from_preferences: 12000`, `canon_facts_from_diegetic_artifacts: 12000`, `branching_story_health_audit: 12000`, `story_character_profile: 12000`, and `8000` for `story_fact_promotion_to_canon` plus remaining task types. Packet fitting also enforces the configured serialized-response ceiling (`task_header.harness_ceiling_chars`, default `60000`, override with `WORLDLOOM_MCP_HARNESS_CEILING_CHARS`) minus `task_header.envelope_overhead_reserve_chars` (default `4000`) so successful inline responses stay below the MCP harness limit after response-envelope overhead. If the fully assembled packet would exceed that effective ceiling, the server writes the full packet under its tool-results directory (`WORLDLOOM_MCP_TOOL_RESULTS_DIR` override) and returns `task_header.delivery_status: 'persisted_with_summary'` plus `governing_summary` inline; story-pipeline summaries include `governing_summary.story_bundle_context_summary`. `packet_incomplete_required_classes` errors include `retry_with: { token_budget }` only when the token budget is the binding constraint under the current harness ceiling; when `minimum_required_harness_ceiling_chars` exceeds `effective_harness_ceiling_chars`, no budget retry can satisfy the current operator environment, so the error omits `retry_with` and exposes top-level `fallback_advice` for targeted `get_record` / `get_records` / `get_record_field` recovery. Optional `delivery_mode: 'full' | 'summary_only'` (default `'full'`) selects per-node payload shape — `summary_only` omits `body_preview` and emits a <=100-char `summary` field per node, useful when only a "what's relevant" index is needed. Task-critical classes may additionally carry `full_body` in `local_authority`, `governing_world_context`, or `exact_record_links`; `task_header.full_body_classes_delivered` reports which live node classes were delivered, `task_header.governing_full_body_priority` reports whether governing invariant and Mystery Reserve bodies are reserved for the task type, and `truncation_summary.full_body_downgrades` reports budget downgrades for opportunistic bodies. For `character_generation`, `diegetic_artifact_generation`, `story_bootstrap`, `story_character_profile`, `story_turn_cycle`, `commitment_block_authoring`, `branching_story_health_audit`, and `story_fact_promotion_to_canon`, governing invariant and Mystery Reserve full bodies are reserved before opportunistic layers, and insufficient budget/ceiling returns `packet_incomplete_required_classes` rather than silently downgrading them. See `docs/CONTEXT-PACKET-CONTRACT.md` §Index + Follow-Up Retrieval Pattern, §Fast-Summary Inline Delivery, §Task-Aware Full-Body Delivery, and §Delivery Modes for the documented retrieval pattern that complements packet assembly.

- `mcp__worldloom__find_named_entities(names, story_slug?, node_type_filter?)` — searches the entity registry's `canonical_name`, `entity_aliases.alias_text`, `scoped_references.display_name`, and `scoped_reference_aliases.alias_text` surfaces against the world index. Optional `story_slug` adds `story_local_matches[]` from indexed story-bundle records alongside world-canon matches. Optional `node_type_filter` restricts each canonical match's `mentions_by_node_type[]` groups to those node types and drops canonical matches with no remaining mention groups; `[]` returns no canonical matches. It does not perform a lexical scan over prose body content such as section bodies, diegetic-artifact bodies, character dossiers, or adjudication prose. - `mcp__worldloom__allocate_next_id(world_slug, id_class, story_slug?, audit_id?)` — allocates append-only IDs using the FOUNDATIONS-002 unpadded numeric convention (`M-1`, not `M-0001`). Most world-scoped classes allocate from the world's index; `EPE` scans `worlds/<slug>/pressure-events/EPE-*.md` directly because pressure-event cards are hybrid, pre-canon files, and `STORY` scans `worlds/<slug>/stories/*/STORY_KERNEL.md` frontmatter for `story_id` because `STORY_KERNEL.md` is a story-root primary-authored file rather than a bundle-scoped atomic record. Pipeline-scoped proposal IDs use `world_slug: "__pipeline__"` with `id_class: "NWB"` for `world-proposals/batches/NWB-*.md` and `id_class: "NWP"` for `world-proposals/NWP-*.md`. Story-bundle-scoped IDs use `story_slug` and scan `worlds/<slug>/stories/<story_slug>/_source/<class>/`, including `PG`, `SE`, `SF`, `BEL`, `OBL`, `CNSQ`, `THR`, `SREL`, `STINT`, `SLT`, `STLOC`, `STOBJ`, `BR`, `CHC`, `STENT`, `STSTAT`, and story-local `DA`; when `worlds/<slug>/` exists but `stories/<story_slug>/` does not yet exist, these story-bundle-scoped classes return `<CLASS>-1` for bootstrap without creating the story directory. `SLB` scans `worlds/<slug>/stories/<story_slug>/storylet-batches/SLB-*.md`, `SAU` scans `worlds/<slug>/stories/<story_slug>/audits/SAU-*.md`, and `SP` scans `worlds/<slug>/stories/<story_slug>/story-promotions/SP-*.md` plus `SP-*-proposal-package.yaml` sidecars. Sub-audit-scoped `RSP` requires both `story_slug` and bare `audit_id` (`SAU-<integer>`) and scans `worlds/<slug>/stories/<story_slug>/audits/<audit_id>/remediation-storylet-proposals/RSP-*.md`.
- `mcp__worldloom__allocate_many_ids(world_slug, allocations)` — batch form for bootstrap and reservation workflows that need several IDs in one MCP round trip. `allocations` is a non-empty ordered array of `{id_class, story_slug?, audit_id?}` entries using the same scope rules as `allocate_next_id`. The response preserves request ordering as `allocations: [{id_class, allocated_id}]`; repeated entries for the same world/class/story/audit scope increment monotonically within the batch, so two fresh `BEL` entries for one bundle return `BEL-1`, then `BEL-2`. If a later entry fails, the error includes `details.successful_allocations` and `details.failed_allocation_index` for reconciliation.
- `mcp__worldloom__describe_capabilities()` — returns the running server's `build_info` (`git_commit_hash`, server-start `build_timestamp`, `source_schema_hash`) plus registered tool names, descriptions, and enum-valued input contracts such as `get_context_packet.task_type`, `allocate_next_id.id_class`, `allocate_many_ids.allocations[].id_class`, and `list_records.record_type`. Use this when a skill or ticket needs to verify the deployed MCP server accepts a newly added enum value after source changes.
- `mcp__worldloom__describe_envelope_schema(op_kind?)` — returns the patch-plan envelope JSON Schema plus per-operation payload schemas for `validate_patch_plan` / `submit_patch_plan`. Pass an `op_kind` such as `create_cf_record` or `create_slt_record` to limit the response to one operation; omit it to retrieve every current patch operation. Inline responses carry `delivery_status: "inline"`. Oversized unfiltered responses persist the full inline-shaped JSON and return `delivery_status: "persisted_with_summary"` with `summary.available_op_kinds` and slice hints such as `op_schemas.create_cf_record`. The response cites the source contract paths and includes referenced record schemas for payload keys such as `cf_record`, `adjudication_frontmatter`, `char_record`, `da_record`, `belief_record`, `storylet_record`, and `story_diegetic_artifact_record`. For `create_slt_record`, `referenced_schemas` also includes `https://worldloom.local/schemas/predicate-dsl-grammar.schema.json`, which describes the closed predicate DSL's per-predicate required arguments and ID patterns for storylet preconditions.

`record_type` and `node_type` are related but not interchangeable vocabulary layers. `list_records.record_type` is the operator-facing retrieval vocabulary. `get_record_schema.node_type` exposes only current validator-backed schema files, including `belief_record` for BEL story records, `story_status_record` for STSTAT story records, `story_plan_record` for STPLAN records, and `story_emotion_record` for STEMO records.

### Retrieval metadata and patch payloads

Retrieval tools expose `record_kind` as response metadata on parsed atomic and story-bundle records so clients can discriminate returned record classes. YAML records under `worlds/<slug>/_source/` and story-bundle `_source/` directories do not store that field. Patch validation accepts a matching optional `record_kind` discriminator in authored-record payloads, which lets retrieval-shaped records be copied into patch-plan constructors without `additionalProperties` failures; mismatched discriminators still fail schema validation.

### Per-op payload-shape validation

`validate_patch_plan` and `submit_patch_plan` validate the envelope wrapper before any pre-apply validators or engine staging run. For world-canon `create_*_record` ops, that envelope-shape pass also verifies the inner payload has the canonical record-id field. `create_ch_record` requires `payload.ch_record.change_id` matching `^CH-\d+$`; `create_cf_record`, `create_inv_record`, `create_m_record`, `create_oq_record`, `create_ent_record`, and `create_sec_record` require `id` on their respective payload records. A malformed create payload returns `status: "skipped"`, `validators_run: []`, and an `invalid_input` reason naming the exact payload path instead of continuing into overlay construction and producing downstream orphan-reference verdicts.

## Retrieval policy

Exact id > exact canonical entity > exact structured record edge > exact scoped reference > weighted lexical. Lexical-only candidates can still be nudged by locality bonuses (authority-bearing node types plus `references_record` / `references_scoped_name` edges), but those bonuses never outrank a higher trust-tier band. Per-task-type ranking profiles live in `src/ranking/profiles/`.

## Approval token

HMAC-signed; single-use; default 20-minute expiry (configurable). Secret at `tools/world-mcp/.secret` (gitignored, generated on first signer invocation if absent).

Skills issue tokens via the canonical CLI:

```bash
node dist/src/cli/sign-approval-token.js <plan-path> [--expiry-minutes <n>]
```

The CLI reads a JSON patch-plan envelope, computes `canonicalOpHash` for every `patches[]` entry, and emits the base64 token to stdout. The token binds `plan_id + world_slug + patch_hashes + issued_at + expires_at`. See `docs/HARD-GATE-DISCIPLINE.md` §Issuing a token for the full skill-side flow.

`--expiry-minutes` defaults to 20, accommodating the 50KB+ envelopes typical of full canon-addition submissions; the engine's verifier only checks `expires_at <= now` and accepts longer windows. Override via flag or `WORLD_MCP_TOKEN_EXPIRY_MIN` env var.

## Patch-plan CLIs

Large patch-plan envelopes can bypass MCP transport while still using the same handler code as the MCP tools:

```bash
node tools/world-mcp/dist/src/cli/validate-patch-plan.js <plan-path>
node tools/world-mcp/dist/src/cli/submit-patch-plan.js <plan-path> <token-path>
```

Invoke both patch-plan CLIs from the project root or active git worktree root (the directory containing `worlds/`, `tools/`, and `docs/`). The CLI/engine path resolves world state from `process.cwd()` and opens the index at `worlds/<slug>/_index/world.db` via `tools/world-index/src/index/open.ts` `indexDirectoryForWorld`; running from another cwd can surface as `Index missing for world '<slug>'` even when the index exists under the repo root.

`validate-patch-plan` prints the same status object as `mcp__worldloom__validate_patch_plan`, including `validators_run[]`: `pass` exits 0 on stdout; `fail` and `skipped` exit 1 on stderr. When a malformed envelope has multiple shape errors, `skipped.details.field` names the first offending path and `skipped.details.additional_errors[]` lists the remaining invalid-input errors. `submit-patch-plan` prints the same `PatchReceipt` / error family as `mcp__worldloom__submit_patch_plan`; it requires a signed approval token file.

The patch-plan CLIs also serve as a fresh-process workaround for the stale-validators-bundle case documented in `docs/MACHINE-FACING-LAYER.md`: when the running MCP server holds a pre-rebuild `@worldloom/validators` bundle in memory and a full session restart is not immediately available, invoke the corresponding CLI directly. Same handler wiring, same validation status object, same `PatchReceipt` / error family.

## Configuration

Registered via `.mcp.json`. For historical prior art, see `archive/specs/SPEC-02-retrieval-mcp-server.md` §`.mcp.json` (example).

The built stdio entrypoint is `dist/src/server.js`, so a local MCP config uses:

```json
{
  "mcpServers": {
    "worldloom": {
      "command": "node",
      "args": ["tools/world-mcp/dist/src/server.js"],
      "env": {}
    }
  }
}
```
