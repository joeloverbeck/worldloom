# Pre-flight and World-State Prerequisites

This reference covers what must be loaded into context before Phase 1 acts (the World-State Prerequisites contract) and the procedural Pre-flight check that validates inputs and assembles state for the rest of the page-cycle turn.

## World-State Prerequisites

Before this skill acts, it MUST receive (per FOUNDATIONS §Tooling Recommendation and §Canonical Storage Layer):

- `docs/FOUNDATIONS.md` — read at Pre-flight. Load-bearing sections at runtime: §Story Bundles §5 (Validation Rules at Story Scope — Rules 1/4/5/7 govern story-scope records; Rules 2/3/6/11/12 govern world-canon-mutation surfaces such as `canon-addition` / `propose-new-canon-facts` / `create-base-world` and are NOT story-scope validators by default), Default Reality + Rule 6 (canon-promotion handoff at Phase 4.5), and §Tooling Recommendation (whole-class enumeration authority for class-bounded firewalls). Other sections are discipline-anchoring rather than runtime-load-bearing. Operational mapping per phase: Rule 5 (No Consequence Evasion at story scope) governs Phase 1 four-way routing; Rule 7 (Mystery Reserve Preservation) governs Phase 4 storylet selection; Rule 6 (No Silent Retcons, applied at story scope by analogy) governs Phase 5 append-only supersession discipline; the same rules govern Phase 7 prose render constraints, Phase 9 validation gates, and the Phase 4.5 canon-promotion handoff to `story-fact-promotion-to-canon`.
- `worlds/<world-slug>/WORLD_KERNEL.md` — primary-authored; read directly per FOUNDATIONS §Canonical Storage Layer §Authored-primary surfaces. Provides genre/tonal contract that grounds Phase 7 prose render.
- `worlds/<world-slug>/ONTOLOGY.md` — primary-authored; read directly. Provides Categories + Relation Types for Phase 2 impact analysis vocabulary alignment.
- `worlds/<world-slug>/stories/<story-slug>/STORY_KERNEL.md` — direct Read (story-bundle root file, not engine-routed). Provides designing principle, content_intensity_baseline, mysteries_in_play[], invariants_acknowledged[], execution_mode_default.
- `worlds/<world-slug>/stories/<story-slug>/_source/pages/<parent_page_id>.yaml` — direct Read (Hook 2's world-canon read redirection matches `worlds/<slug>/_source/...`; it does not match nested story-bundle `_source` paths). Bedrock state for this turn — `parent_page.state_snapshot` is the authoritative branch state at the fork point.
- The records cited by `parent_page.state_snapshot` — direct Read of `worlds/<world-slug>/stories/<story-slug>/_source/<class>/<ID>.yaml` for every cited SF, OBL, CNSQ, THR, SREL, STINT, SLT, STLOC, STOBJ, BR.
- Pages along `parent_page.branch_path` for prose continuity — last ~2 pages of `worlds/<world-slug>/stories/<story-slug>/pages-prose/PG-NNNN.md` ALONG THIS BRANCH ONLY. The engine NEVER reads sibling-branch pages; Phase 9's recursive reference closure validation enforces structurally.
- Current storylet pool — `worlds/<world-slug>/stories/<story-slug>/_source/storylets/SLT-*.yaml` filtered by `visibility` block:
  - `visibility.scope == global_author_pool` → visible to all branches.
  - `visibility.scope == branch_prefix_scoped` → visible iff `visibility.visible_branch_path_prefix` is a prefix of `this_page.branch_path`.
  - `visibility.scope == branch_scoped` → visible iff `created_at_page ∈ this_page.branch_path`.
- **Premise-and-state-bounded world-canon retrieval** via `mcp__worldloom__get_context_packet(world_slug, task_type='story_page_cycle', seed_nodes=[<resolved entity:slug ids from cast_present STENT anchors + parent_page.current_location + active period>], token_budget=18000)`. Cast-present STENT seed-node resolution follows the story-identity resolver rule: character mirrors resolve through `STENT.character_id` to the world `CHAR-NNNN` dossier / character name and intentionally keep `STENT.world_ent_id: null`; non-CHAR world mirrors resolve through `STENT.world_ent_id`; `story_only: true` STENTs with no world anchor are not world-canon seed nodes unless another explicit world anchor exists. The `seed_nodes` are resolved via `mcp__worldloom__find_named_entities(names)` BEFORE the context-packet call.
  - **Targeted-retrieval as primary path** (per FOUNDATIONS §Tooling Recommendation's "directly or via the documented context-packet + targeted-retrieval pattern"): when (i) the operator can identify the load-bearing record IDs directly from `parent_page.state_snapshot` (which already cites every active SF / OBL / CNSQ / THR / SREL / STINT / SLT / STLOC / STOBJ / BR for the branch), (ii) `seed_nodes` resolution is not needed for cross-reference completeness (the page tick stays inside an already-localized cast and current_location with no novel entity introductions requiring fresh world-canon SEC anchoring), AND (iii) the whole-class M + INV firewall loads below run regardless, **direct `get_records(record_ids=[...])` on the cited state-snapshot IDs + targeted `get_record` on referenced CFs** is a valid primary retrieval path equivalent to the context-packet call. This matches the actual page-tick workload for continuation cases where `parent_page.state_snapshot` already encodes the localized state. The `get_context_packet` call remains the primary path when novel entity introductions, fresh active period transitions, or cross-cutting world-canon SEC retrieval (geography / institutions / timeline) are needed for prose grounding — those are exactly the cases `seed_nodes` resolution + premise-bounding addresses. **Note that the targeted-retrieval primary path does NOT cover the latest-CH retrieval needed for `state_snapshot.canon_revision` audit-trail** — that field is auto-included only by the `get_context_packet(task_type='story_page_cycle')` governing-context per `archive/tickets/MCPENH-012-register-story-page-cycle-task-type.md`. Operators taking the targeted-retrieval primary path must separately obtain the latest CH-NNNN — e.g., via `mcp__worldloom__list_records(world_slug, record_type='change_log_entry', fields=['record_id'])` and pick the highest, OR by calling `get_context_packet(task_type='story_page_cycle', token_budget=2000)` solely for the audit-trail field. Filesystem-listing of `_source/change-log/` directly is operator-improvisation rather than a documented retrieval path.
  - **Packet-too-large fallback**: if the packet returns `delivery_status='persisted_with_summary'` OR `packet_incomplete_required_classes` OR non-empty `truncation_summary.dropped_layers`, reduce `seed_nodes` and retry; use `governing_summary` inline; `get_records(record_ids=[...])` for known-id sets; `get_persisted_packet_slice` for structured persisted-packet recovery. Same fallback shape as `branching-story-bootstrap`. Note that `get_records` itself can return `delivery_status='persisted_with_summary'` when the batch is oversized (e.g., a multi-CF batch where each CF body is large); the recovery is identical — individual `get_record(record_id)` calls for the records actually needed inline, OR `get_persisted_packet_slice(persisted_path, slice_path)` when structured persisted-data recovery is preferable for batch reuse. The chained-overflow case is structurally the same as packet overflow; the per-record retrieval path remains the canonical recovery.
- **Whole-class Mystery Reserve firewall load** via `mcp__worldloom__list_records(world_slug, record_type='mystery_record', include_full_body=true)` — every M record body is needed at Phase 4 (storylet `mystery_safety` cross-check), Phase 4.5 (per-claim resolution authority routing), and Phase 9 gate 1 (no `forbidden`-status M resolved by any applied op or rendered prose). Whole-class enumeration is authorized for skills "whose firewall is class-bounded" per FOUNDATIONS §Tooling Recommendation.
- **Whole-class Invariant audit load** via `mcp__worldloom__list_records(world_slug, record_type='invariant_record', include_full_body=true)` — every INV record body is needed at Phase 3 (continuation-feasibility INV check) and Phase 9 gate 2 (all `applied_event_ops` respect every world INV).
- **`list_records` response-size fallback**: before falling back to persisted-file recovery, prefer server-side filters on predictable hard-filter loads. For Phase 4 storylet-pool narrowing, call `list_records(record_type='storylet_record', story_slug=<story>, filters={shape: [...], content_intensity: [...], 'visibility.scope': '...' }, fields=[...])`; filters run before projection/full-body wrapping and support scalar exact matches, array any-of matches, and dotted paths such as `visibility.scope` / `visibility.allowed_branch_ids`. **The `fields` projection is asymmetric with filters' dotted-path support: `fields` accepts only response-shape top-level keys (e.g., `record_id`, `title`, `shape`, `content_intensity`) and rejects dotted-path or nested-body keys (e.g., `body.theme_tags`, `salience_baseline`) with `invalid_input: Unknown list_records fields key '<key>'`. For nested-field access, prefer `include_full_body=true` and project on the consumer side via `jq`; do not attempt to reach inside the body via `fields`.** If the filtered response still exceeds the MCP transport budget, use the persisted path reported by the tool response and fall back to `jq` extraction. Probe structure with `jq 'type, length, .records[0]'`, then filter by shape/intensity/visibility with `jq '[.records[] | select(.body.shape == "X")]'` for full-body results, or by projected top-level fields when `fields=[...]` was passed. Direct file Read of `_source/<class>/*.yaml` is also valid for known-id batches, but server-side `filters` are the first-choice Phase 4 hard-filter path when the storylet pool is large.

If `worlds/<world-slug>/` is missing, abort and instruct the user to run `create-base-world` first. If `worlds/<world-slug>/stories/<story-slug>/` is missing, abort and instruct the user to run `branching-story-bootstrap` first. If `parent_page_id` does not exist or does not belong to this story, abort with a specific-id error.

Direct `Read` of `worlds/<world-slug>/_source/<world-subdir>/` is redirected to MCP retrieval by Hook 2 — do not bulk-read world canon. Direct `Read` of `worlds/<world-slug>/stories/<story-slug>/_source/<story-subdir>/` is the correct surface (Hook 2's match pattern is `worlds/<slug>/_source/...` which does NOT match the nested story bundle).

## Pre-flight Check

Run before Phase 1; abort if any precondition fails.

- Load `docs/FOUNDATIONS.md` into working context.
- **Verify FOUNDATIONS-in-context before proceeding**: confirm that `docs/FOUNDATIONS.md`'s content is loaded in this session's context — via direct Read in this session, or via system-reminder injection that reproduces the document verbatim (CLAUDE.md system-reminder content does NOT satisfy this criterion unless it reproduces FOUNDATIONS.md verbatim, since references to FOUNDATIONS principles in CLAUDE.md are operator-summary, not the document itself). If FOUNDATIONS is not in context, halt Pre-flight, Read it, and resume — CLAUDE.md §Non-Negotiables forbids skipping this load: *"If a workflow's pre-flight doesn't explicitly load it, the workflow is incomplete — stop and add the load before proceeding."* Bare reliance on prose-discipline is insufficient; this verification is the structural surface that makes HARD-GATE condition (a)'s FOUNDATIONS-load mandate self-checkable rather than purely cultural.
- Normalize `world_slug` (strip `worlds/` prefix; verify `[a-z0-9-]+`); resolve `worlds/<world-slug>/`. Abort if missing — instruct the user to run `create-base-world` first.
- Validate `story_slug` is kebab-case (`[a-z0-9-]+`); resolve `worlds/<world-slug>/stories/<story-slug>/`. Abort if missing — instruct the user to run `branching-story-bootstrap` first.
- Validate `parent_page_id` exists at `worlds/<world-slug>/stories/<story-slug>/_source/pages/<parent_page_id>.yaml` and that the loaded record's `story_id` matches the `STORY-NNNN` resolved from `STORY_KERNEL.md`. Abort with a specific-id error otherwise.
- **§14 hard pre-flight block — parent.prose_status check.** After reading the parent PG record, inspect `parent.prose_status`. If `parent_page_id != null` AND `parent.prose_status != "rendered"`, ABORT pre-flight with the directive:

  ```
  Parent page <PG-NNNN> has prose_status=<status>. Run
  branching-story-page-prose-finalize on the parent before authoring
  this page's plan, so §14 (Recent prose continuity) can inline the
  parent's rendered prose.
  ```

  This applies to both straight-line continuation AND fork-from-non-leaf — any parent page must be rendered before its child can be planned. The check serializes the authoring loop: bootstrap-plan → finalize → page-cycle-plan → finalize → page-cycle-plan → ..., guaranteeing the §14 (Recent prose continuity) plan section always has rendered prose to inline. The check is structurally absolute regardless of `execution_mode`; `interactive_runtime` cannot proceed against a `pending`-prose parent because the plan body cannot be assembled without §14 source material.
- Validate exactly one of `{chosen_choice_id, manual_action_text}` is present. Abort if neither or both.
- If `chosen_choice_id` is provided: load `_source/choices/<chosen_choice_id>.yaml` and verify it appears in `parent_page.emitted_choices`. Abort with a specific-id error if missing or out-of-set.
- Resolve `execution_mode`: input override → `STORY_KERNEL.execution_mode_default` → `authoring`.
- Allocate the next `PG-NNNN` for this story via `mcp__worldloom__allocate_next_id(world_slug, id_class='PG', story_slug=<story_slug>)`.
- Detect fork via typed MCP query: `mcp__worldloom__list_records(world_slug, record_type='page_record', story_slug=<story_slug>, filters={parent_page_id: <parent_page_id>}, fields=['record_id'])` returns the page records whose `parent_page_id` field references the parent. If the response's `records[]` is empty, the parent is a leaf and this run extends `parent_page.branch_id` along the same logical branch via supersession of the prior BR record (continuation case). If `records[]` is non-empty, the parent already has descendants and this run produces a NEW (fork) branch — the existing descendants stay on their original branch and the fork is structurally a sibling lineage. The typed query is the canonical primary path; filesystem fallback (`ls _source/pages/PG-*.yaml` followed by per-file Read of each PG's `parent_page_id` field) remains valid when the world index is unavailable or stale, but the index-backed query is faster, scales to large branch trees, and matches the §Tooling Recommendation's "LLM agents should never operate on prose alone" commitment. In BOTH the fork and continuation cases, allocate the next `BR-NNNN` at pre-flight via `mcp__worldloom__allocate_next_id(world_slug, id_class='BR', story_slug=<story_slug>)`. What differs between fork and continuation is what the new record's `logical_id` carries (continuation: existing branch's logical_id, paired with `supersedes` pointing to the prior BR record per Phase 11 §1a's `create_br_record` op; fork: a fresh logical_id with no supersedes), not when the id is allocated.
- **Pre-allocate the per-class IDs the envelope will populate.** For each id-class the turn will create records in (`SF` / `OBL` / `CNSQ` / `THR` / `SREL` / `STINT` / `SE` / `SLT` / `STLOC` / `STOBJ` / `DA` / `CHC`, plus `PG` and `BR` per the bullets above), call `mcp__worldloom__allocate_next_id(world_slug, id_class=<CLASS>, story_slug=<story_slug>)` once per class to obtain the next free ID. Conditional classes such as `CNSQ`, `STLOC`, `STOBJ`, and story-local `DA` are allocated only when this turn actually emits the corresponding op, and the matching `expected_id_allocations` key is omitted otherwise. **ARCTRACE-NNNN is NOT pre-allocated at page-cycle pre-flight** post-PROSESPLIT-007 — page-cycle no longer emits ARC_TRACE; ARCTRACE allocation moves to `branching-story-page-prose-finalize` pre-flight, which allocates the id and emits the `create_arc_trace_record` op in its envelope. Filesystem-counting at envelope-build time is error-prone in the presence of supersession chains (e.g., `OBL-0007` superseded by `OBL-0010` leaves gaps in the filename sequence that a manual count can misread by counting visible files rather than tracking the supersession-resolved highest id); the allocator's count is canonical and matches what the patch engine's `id_allocation_race` check enforces at submit time. The same per-class pre-allocation discipline applies in `branching-story-bootstrap` per its `references/engine-envelope-shape.md` §3 — page-cycle envelopes are smaller (typically 10-20 records vs bootstrap's ~75) but the failure mode is identical, and supersession-chain gaps make manual counting more error-prone for runtime page-ticks than for fresh bootstrap allocation.
- Read `worlds/<world-slug>/WORLD_KERNEL.md`, `worlds/<world-slug>/ONTOLOGY.md`, and `worlds/<world-slug>/stories/<story-slug>/STORY_KERNEL.md` directly.
- Direct Read of `_source/pages/<parent_page_id>.yaml` and every record cited in `parent_page.state_snapshot` (objective_facts, apparent_facts, disputed_facts, reader_known_facts, belief_state_by_actor.*, rumor_state, obligations_*, consequences_*, threads_active, relationships_current, intentions_current, cast_present, current_location, accessible_locations, objects_in_scope, inventory_by_entity.*).
- Direct Read of last ~2 pages along `parent_page.branch_path` from `pages-prose/PG-NNNN.md` (prose continuity context — branch only, never sibling branches).
- Load current storylet pool — `_source/storylets/SLT-*.yaml` filtered by `visibility` per Phase 4 hard filters.
- Resolve premise-relevant entities: for each STENT in `cast_present`, apply the story-identity resolver rule. Character mirrors use `STENT.character_id` to load the linked `CHAR-NNNN` dossier / character name and do not require `world_ent_id`; non-CHAR world mirrors follow `STENT.world_ent_id`; `story_only: true` STENTs with no world anchor are skipped as world-canon seed nodes unless another explicit anchor exists. For `parent_page.current_location` (an STLOC), follow `world_geo_anchor` (the STLOC's SEC-GEO-NNN anchor) to the world geography section; collect the active period. Resolve to `entity:<slug>` ids via `mcp__worldloom__find_named_entities(names)` — STENT names from the linked CHAR dossier or non-CHAR mirrored entity, and STLOC names from the STLOC's `name` field combined with the resolved SEC's region descriptor.
- Load premise-bounded world-canon retrieval via `mcp__worldloom__get_context_packet(world_slug, task_type='story_page_cycle', seed_nodes=[<resolved ids>], token_budget=18000)` OR equivalent targeted retrieval (per §World-State Prerequisites — direct `get_records` on `parent_page.state_snapshot`-cited IDs + targeted `get_record` on referenced CFs is a valid primary path when conditions (i)-(iii) of the targeted-retrieval-as-primary-path sub-bullet hold). Apply the packet-too-large fallback per §World-State Prerequisites if the packet path is taken and the response signals overflow.
- Load whole-class Mystery Reserve firewall: `mcp__worldloom__list_records(world_slug, record_type='mystery_record', include_full_body=true)`.
- Load whole-class Invariant audit: `mcp__worldloom__list_records(world_slug, record_type='invariant_record', include_full_body=true)`.
- Read current world canon revision and record it as `state_snapshot.canon_revision` on the new page (audit trail per the proposal's §World-Canon Propagation Note — supports forensic reconstruction when canon promotions later land between branch ticks). Primary path: `mcp__worldloom__list_records(world_slug, record_type='change_log_entry', fields=['record_id'])`, then choose the highest-numbered `CH-NNNN` in the returned records. If the world has no CH records yet (genesis world before first canonization), set `state_snapshot.canon_revision: null`. If the context packet already supplied the governing current revision, use that value instead of a duplicate query. Direct filesystem listing of `worlds/<world-slug>/_source/change-log/` is offline/debug fallback only, not the documented primary retrieval path.
- Confirm content_policy block (NC-21 verbatim text from `templates/content-policy.txt`) is loaded for downstream prompt assembly. Without it, Phase 7 cannot legitimately author a plan whose §2 inlines the content_policy verbatim. This is the FIRST condition of the HARD-GATE.
