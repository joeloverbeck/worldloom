# Phase 9: Validation Gates (Canon Safety Check phase)

Reference for `branching-story-bootstrap` Phase 9 — the 19-gate canon-safety audit that gates HARD-GATE Phase 10 approval. Each gate must record PASS with a one-line rationale into `STORY_KERNEL.md`'s `validation_trace` field — except `prose_ledger_consistency` (gate 10), which records `DEFERRED — awaiting prose render` at bundle commit and is later flipped to PASS/FAIL by `branching-story-page-prose-finalize` Phase 5. Any FAIL halts the bootstrap and routes to the responsible upstream phase. A bare "PASS" without rationale is treated as FAIL per the FOUNDATIONS skill discipline.

**Whole-class loads from Pre-flight power gates 1, 2, and 9**: M-record full bodies for gate 1's `forbidden`-status check + `M_resolution_claims` interrogation; INV-record full bodies for gate 2's `break_conditions` audit across the initial SF / THR / OBL / SLT-precondition / state_snapshot / CHC-likely-effects surface. Without those whole-class loads, Phase 4 and Phase 9 cannot honor their canon-safety contract.

**Gates 14-18 — PG-0001 scene-commitment validator alignment**: these five gates mirror the SPEC-20 / SPEC-22 page-cycle validator surfaces at the bootstrap root. Four are root-special-case gates because PG-0001 has no selected arc and no ARC_TRACE. `choice_worthiness_completeness` applies non-vacuously to the emitted CHCs.

**Gate 19 — plan-completeness backstop**: this gate is a defense-in-depth backstop to Phase 7's plan-completeness post-LLM check. Phase 7 routes a missing-section / unresolvable-id / malformed-frontmatter failure as a re-prompt within its own 3-cycle budget; if Phase 7 exhausts the budget and still escalates to Phase 10, Phase 9 gate 19 re-fires the check and routes back. The two-layered enforcement matters because the plan IS the prompt — corrupt plans corrupt the rendered prose silently.

**DEFERRED gates 10 + 16 (conditional)**: at bundle commit there is no rendered prose to ledger-check (gate 10) and at non-root pages no rendered prose to align with the arc's evidence spans (gate 16). Both gates are recorded as `DEFERRED — awaiting prose render` on `PG.deferred_validation_trace` and re-evaluated by `branching-story-page-prose-finalize` Phase 5 after the user supplies `pages-prose/PG-0001.md`. Gate 16 at PG-0001 root is structurally not deferrable (no arc selected, no evidence to align); it auto-PASSes at bundle commit as documented in the table.
