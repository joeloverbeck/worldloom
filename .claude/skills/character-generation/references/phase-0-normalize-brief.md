# Phase 0: Normalize Character Brief

Parse `character_brief_path` if provided; otherwise interview the user. Extract:

**Required inputs** (abort Phase 0 if any remain unresolved after interview):
- `current_location` — bound to a specific ENT-NNNN region or settlement (resolved via `find_named_entities` + `get_neighbors` against SEC-GEO context); where the character is at the dossier's recorded `date`
- `place_of_origin` — bound to an ENT region or settlement when the origin lies within the world's named geography. Three-part test:
  - (a) **default to `current_location`** when the brief is silent AND the character's self-concept would plausibly include origin detail (parents, home-town, birth-village) that the author has simply not yet specified — i.e., the silence is incidental;
  - (b) **record as "deliberately withheld" in the dossier `notes`** when EITHER the brief does not commit an origin AND the character's self-concept does not reference one (the character treats origin as outside the narrative frame), OR the brief explicitly notes the character has severed origin ties;
  - (c) **out-of-stage origin** when the brief explicitly commits an origin that is a real-world or otherwise-legitimate location outside the world's named geography (e.g., American expat in a Spanish-Basque-coast realist world; off-continent migrant in a region-bounded fantasy; out-of-system traveler in a single-system-scoped science-fiction world). Record the origin as free-text with an explicit `(out-of-world; not bound to a worlds/<slug>/_source/entities/ENT record)` annotation, and document the disposition in `notes`. The institutional embedding (Phase 2) carries the load-bearing structural axes (residency status, expat-class position, migrant-cohort affiliation, language facility); the unbound origin string is biographical context, not an entity-binding claim.

  The three-part test disambiguates the silence-plus-self-concept case (a), the silence-alone case (b), and the explicit-out-of-stage case (c); applying (a) when (b) fits produces a false origin-claim, applying (b) when (a) fits loses a small but real piece of character grounding, and applying (a) or (b) when (c) fits forces a false in-world binding for a legitimately external origin.
- `date` — resolved against the world's chronotope (`WORLD_KERNEL.md`) and SEC-TML records
- `species` — bound to a cluster named in SEC-PAS records
- `age_band` — free-form but must be plausible for the species's lifespan per SEC-PAS
- `social_position` — bound to an institutional stratum in SEC-INS
- `profession` / livelihood — bound to an institution or trade in SEC-INS / SEC-ECR
- `kinship_situation` — per the kinship logic in SEC-INS (family/clan/household) and SEC-ELF (ordinary kinship norms)
- `religious_ideological_environment` — bound to an institution, cult, or folk practice named in SEC-INS or SEC-ELF
- `major_local_pressures` — cross-referenced against SEC-GEO (ecological), SEC-ECR (scarcity), SEC-INS (political), and SEC-TML (historical residues)
- `intended_narrative_role` — free-form (protagonist / witness / antagonist / foil / narrator for diegetic artifact / background texture)

**Optional inputs** (recorded in dossier `notes` if provided):
- central contradiction
- desired emotional tone
- desired arc type
- taboo or limit themes to avoid

**Conditional context-packet expansion**: if any declared input touches magical or technological capability (checked against `ONTOLOGY.md` magic-practice / technology categories or capability CFs in the packet), expand retrieval via `mcp__worldloom__search_nodes(node_type='section', filters={file_class: 'magic-or-tech-systems'})` and `get_record(sec_id)` for each relevant SEC-MTS record. Skip otherwise to avoid context bloat on ordinary-laborer characters.

**Region/era descriptor binding fallback**: `find_named_entities` performs exact-match resolution against the entity registry. Region descriptors (e.g., `drylands`, `canal-heartland`) and era descriptors (e.g., `Charter-Era`, `Incident Wave`) that appear only inside compound tokens (`drylands south`, `Charter-Era integration`) may return empty — they are not registered as standalone entities. For those, use `mcp__worldloom__search_nodes(world_slug, query='<descriptor>')` to discover the SEC and CF records that contain the descriptor, then bind the descriptor to those records by reference rather than to a single `ENT-NNNN` id.

**Slug derivation** (if not yet done at Pre-flight): kebab-case the character's in-world name (lowercase, punctuation-stripped). **Baseline case**: when the character has only a personal name with no epithet or sobriquet, the slug is the personal name kebab-cased — `rill` for Rill, `aldous` for Aldous, `bertram` for Bertram. **Epithet case**: when the character's name contains a nickname, epithet, or professional sobriquet (a quoted nickname in the brief, a professional byname, a title-as-name), default to **personal-name-first** kebab-case — e.g., `melissa-threadscar` rather than `threadscar-melissa`; `vespera-nightwhisper` rather than `nightwhisper-vespera`. If the world's existing `characters/` directory uses a different convention, match precedent; the convention must be stable within a world for INDEX.md alphabetic ordering to remain semantically coherent over time. If no existing dossiers exist yet, personal-name-first is the default. Re-run the slug-collision check from the Pre-flight final step.

**Rule**: Never advance to Phase 1 with an unresolved required input or an input that cannot be bound to a specific entity in the loaded world files (out-of-stage origins per branch (c) of the `place_of_origin` test are the named exception — they bind to a residency / migration / expat institutional embedding at Phase 2 instead of to a worlds/<slug>/ENT record). A "generic farmer" cannot exist; "a third-generation bondmaid in the Marsh Courts" can.

**Rule (factual claims pre-check against real-world-binding invariants)**: Before binding inputs to world entities, scan the brief's narrative claims for assertions that touch real-world-binding invariants — ONT-2-style rules in realist-Earth worlds (real-world law, biology, economics still bind); baseline-biology rules in fantasy worlds where the world commits to baseline embodiment except for named exceptions; baseline-physics rules in any world where physics binds. If a brief claim contradicts a real-world-binding invariant the world has committed to (e.g., *"the statute of limitations has run out on US murder charges"* in a world where ONT-2 binds real-world US law — US murder has no statute of limitations in any state, so the actual basis for the character's legal protection is double-jeopardy attachment after acquittal), reframe the claim to the legally / biologically / physically correct fact and record the original brief framing as the character's own `wrongly_believes` content (Phase 3) if it is plausible they would hold the inaccurate view, or as a reframing note in `notes` if not. Surface every reframing at Phase 9's deliverable summary so the user can confirm or reject the correction. Catching this at Phase 0 prevents the rework cycle where Phases 1-6 build on a factually-incorrect premise that Phase 7a invariant conformance later flags.

**Rule (continuity)**: If the Pre-flight continuity-preservation read loaded existing-dossier continuity constraints (commitments about the new character recorded in other dossiers' `notes`, `source_basis`, or `Likely Story Hooks`), those constraints are non-negotiable for Phases 1-6. Examples from prior sessions: a silver-split already recorded as "honored" in another dossier cannot be re-opened here; an operation another dossier classifies as CF-0006 extraction cannot be re-classified here as CF-0021 crafter-attempt; a referenced character's age or species-cluster cannot be contradicted. If Phase 1-6 work would require contradicting a constraint, escalate to the user at Phase 9 as a named continuity-conflict item — do not silently override.

**Rule (cross-dossier minor-NPC reconciliation)**: When the brief and an existing dossier reference the same minor NPC with different profession / role / register attribution (e.g., the brief calls a character "tanner" while another dossier names them "gearfitter"), attempt compositional reconciliation — preserve both registers as the same person at different relations (e.g., "tanner-and-gearfitter" for a leatherworker who fits armor) — and record the reconciliation in the new dossier's `notes` block. Operationally compatible roles compose; pick neither as canonical, since both registers are legitimate observers' framings of the same person. If the registers are operationally incompatible (e.g., one dossier names X a magistrate, another names X a bandit-captain — same name, contradictory institutional position), escalate to the user at Phase 9 as a named continuity-conflict item — do not silently pick one. This is distinct from the Rule (continuity) above, which governs commitments about the new character recorded in other dossiers; this rule governs references to *minor NPCs* whose canonical attribution drifts across briefs and dossiers.
